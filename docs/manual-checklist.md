# 수동 체크리스트 (사용자 Mac)

대상: M1 Pro, 내장 XDR, macOS 27.2, Safari 27.2. WebGPU·EDR 밝기·끊김·Safari 확장 동작은 자동 테스트로 검증할 수 없고 사용자 Mac에서 눈으로만 확인된다. (PLAN.md E절)

## 공통 전제

모든 절의 전제는 `docs/install.md` 4장이다: `git pull` → Xcode Run → Safari 완전 종료(⌘Q) 후 재시작 → "서명되지 않은 확장 허용" 다시 켜기(재시작마다 꺼짐). 각 절은 이 전제를 참조만 한다. `scripts/make-xcode.sh`는 최초 설치 때만 쓰며 업데이트에는 실행하지 않는다. 확인하지 못한 항목은 비우지 말고 [미확인]으로 적는다.

## 회귀 빠른 점검

공통 전제 후, 전원 연결·SDR 밝기 중간에서 SDR 영상(DRM 없음) 하나로 한다. 각 항목에 예/아니오와 한 줄을 적는다.

1. 오버레이 표시: YouTube 영상을 재생해 영상 위에 확장 캔버스가 겹치는가, 재생·설정·전체화면 컨트롤이 클릭되는가.
2. HUD 켜고 끄기: popup에서 "페이지 HUD 표시"를 켜면 플레이어 왼쪽 위에 HUD가 뜨고 끄면 사라지는가.
3. 진단 복사: popup 진단 영역을 펼쳐 "복사"로 JSON을 복사한다. `lifecycle.state`가 `active`인가. 진단 모드를 바꿨다면 [정상 모드로]로 되돌린다.
4. HDR·DRM 영상 건너뜀: HDR 표시가 있는 영상은 진단 `lifecycle.skipReason`이 `hdrSource`, EME를 쓰는 영상(YouTube 영화 등)은 `drm`이고 오버레이가 없는가. 이 두 경우와 WebGPU 실패·확장 끔에서는 HUD도 표시되지 않는 것이 정상이며 진단 JSON으로 확인한다.
5. 확장 켜고 끄기: popup의 "HDR 변환"을 끄면 원본으로 돌아가고 켜면 다시 적용되는가(`lifecycle.skipReason`이 `disabled` ↔ 해제).

## 회신 방법

1. export한 JSON을 저장소 `results/result-<M>-<YYYYMMDD>[-조건].json`으로 두고 브랜치에 push한다. (M1 프로브는 `<M>`이 `M1`)
2. 이 체크리스트 사본에 체크 표시와 한 줄 코멘트를 적어 함께 push한다.
3. 스크린샷은 레이아웃 확인용이다. macOS 스크린샷은 EDR 밝기를 증명하지 못하므로 밝기 판정은 JSON의 선택값(`edr.maxDistinctStep`, `edr.encodingMatch`)으로 한다. 노출을 고정한 휴대폰 사진은 선택 사항이다.
4. push 후 `python3 scripts/parse-result.py`로 요약 표를 볼 수 있다("G3 대상(overlay)" 열, 모드별 표, G3 요약 표, visualJudder 포함). 스크립트는 값만 출력하고 판정은 하지 않는다. G1~G3 판정은 Opus가 PLAN.md 게이트 판정 기록에 기입한다.

## JSON 스키마

`docs/result-schema.json` (env, api, edr, perf, flags, errors). `python3 scripts/parse-result.py results/`가 이 스키마로 검증한다(`jsonschema` 모듈이 없으면 필수 키/타입 검사로 대체).

## M7 UX 1단계 확인 절차 (PLAN D-M7 M7-5)

전제: 공통 전제(위). popup 헤더 버전이 `v1.1.0`인지 먼저 본다. 화면 모양은 사용자가 판정하며 Claude가 검증한 항목이 아니다. 확인하지 못한 항목은 [미확인]으로 적는다.

1. **라이트·다크 popup**: macOS 외관을 라이트와 다크로 바꿔 popup을 연다. 배경·글자 대비, 슬라이더가 한 줄 전체 폭인지, 값(%·×)이 바뀌어도 슬라이더가 밀리지 않는지.
2. **HDR 변환 스위치**: 끄면 조정 영역이 흐려지고 "꺼짐" 안내가 나오는지, YouTube 영상이 원본으로 돌아오는지(1초 안). 다시 켜면 복귀.
3. **진단 모드 안내**: 진단 영역에서 모드를 `baseline`으로 바꾼 뒤 popup을 닫았다 다시 연다. 진단 영역이 자동으로 펼쳐져 있고, 일반 영역에 "화질 조정이 잠겨 있습니다" 안내가 있고, [정상 모드로]를 누르면 조정이 다시 풀리는지.
4. **곡선 되돌리기**: 사용자 지정(기본) 곡선 상태에서 프리셋 `정확`을 고르고 상세 슬라이더를 하나 움직인다. "이전 사용자 지정 곡선을 … 바꿨습니다 [되돌리기]"가 보이고, 누르면 이전 값으로 복원되는지.
5. **기본값으로 되돌리기**: 값을 몇 개 바꾼 뒤 버튼을 누르면 "한 번 더 눌러 확인"으로 바뀌고, 3초 안에 다시 누르면 기본값(사용자 지정, 강도 43%, 선명도 0%, 채도 105%, HUD 꺼짐)으로 돌아가는지. 켜기 상태는 유지되는지. 영상 반영 1초 안.
6. **유효 피크**: 기본값에서 `×1.90`이 HDR 강도 슬라이더 아래에 보이는지. 화면 밝기를 최대로 하고 강도를 올려 ×2.0을 넘기면 "화면 밝기 최대에서 … 잘릴 수 있음" 경고가 뜨는지, 낮추면 사라지는지(경고는 고정 헤드룸 표 기준이며 실제 헤드룸이 아님).
7. **진단 복사**: [복사]를 누르면 "복사됨" 표시가 나오는지. 붙여넣은 JSON의 `schemaVersion`이 11인지, 진단 영역 맨 위 "마지막 기록 … 상태 …" 줄이 보이는지. 다른 앱에 붙여넣기 되는지(복사 실패 시 안내 문구도 기록).
8. **HUD**: HUD를 켠다. 2줄이 `프리셋 · 강도 …% 선명도 …% 채도 …%`, 4줄이 `렌더 fps …`로 보이는지. 프리셋 `강조`를 고르면 HUD 라벨도 `강조`인지.
9. **회신**: 진단 JSON 1개를 `results/result-M7-<YYYYMMDD>.json`으로 저장해 회신한다. 측정 조건(화면 밝기, 전원)을 함께 적는다.

판정: (3)(4)(5)(6)이 모두 예이면 M7 완료. (1)(2)(7)(8)은 기록.

## M8 UX 2단계 확인 절차 (PLAN D-M8 M8-7)

전제: 공통 전제(위). 이번에는 **Xcode Run 후 앱을 한 번 실행**해 background와 아이콘이 번들에 들어가게 한다. popup 헤더 버전이 `v1.2.0`인지 먼저 본다. 화면 모양은 사용자가 판정하며 Claude가 검증한 항목이 아니다.

1. **아이콘**: Dock과 Safari 툴바에 새 아이콘이 보이는지, 밝은·어두운 툴바 모두에서 알아볼 수 있는지.
2. **popup 상태 줄**: YouTube 재생 중 "HDR 변환 중". 다른 사이트 탭에서 popup을 열면 "이 탭에서는 동작하지 않음". HDR 영상에서 "이미 HDR 영상". 켜기를 끄면 즉시 "꺼짐".
3. **툴바 배지**: HDR 영상 탭 "HDR", 진단 모드에서 "D", 일반 재생 탭은 배지 없음. **배지가 전혀 안 나오면 background 로드 실패**이니 알려 주면 manifest 형식을 바꾼다.
4. **끄면 회색 아이콘**: HDR 변환을 끄면 툴바 아이콘이 회색으로, 켜면 원래대로.
5. **Option+H**: 누르는 동안 원본, 떼면 즉시 변환 복귀. 다른 탭에는 영향 없음.
6. **Option+Shift+H**: 켜기/끄기, 영상 위 알림 표시. 입력창(검색창)에서 글자 입력 시 동작하지 않음.
7. **상태 알림**: 영상을 바꿀 때 영상 오른쪽 위에 2.5초 알림이 뜨는지(너무 자주·시끄러운지 의견), popup "상태 알림"을 끄면 뜨지 않는지.
8. **HUD 유지**: HUD를 켠 채 DRM 영상(또는 확장 끔)에서 HUD에 이유 문구가 보이는지.
9. **회신**: 진단 JSON 1개를 `results/result-M8-<YYYYMMDD>.json`으로 저장해 회신한다.

판정: (2)(3)(5)(6)이 모두 예이면 M8 완료. (1)(4)(7)(8)은 기록.
