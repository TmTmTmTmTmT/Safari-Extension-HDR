# 설치·사용·문제 해결 가이드

SDR 영상을 실시간으로 확장해 EDR(HDR 밝기)로 보여 주는 Safari 확장입니다. 처음 설치할 때와 7일 만료 후 다시 설치할 때 이 문서를 따릅니다. 확인하지 못한 내용은 `[확인 필요]`로 표시했습니다.

## 1. 개요와 한계

- 주 대상은 YouTube(`https://www.youtube.com/*`)의 DRM 없는 SDR 영상입니다.
- 아래 경우는 의도적으로 건너뛰고 원본 그대로 재생합니다. 오류가 아닙니다.
  - DRM(EME/FairPlay) 영상: 신호가 하나라도 있으면 즉시 아무것도 하지 않습니다. DRM 회피·화면 캡처 우회는 하지 않습니다.
  - 이미 HDR인 영상(PQ/HLG)
  - PiP(화면 속 화면): PiP에서는 원본 재생, 복귀 시 재개되는지는 아직 확인하지 못했습니다(8장).
- 대상 환경: M1 Pro, 내장 XDR, macOS 27.2, Safari 27.2. 다른 환경은 검증하지 않았습니다.
- 밝기 헤드룸은 JS에서 조회할 수 없고 SDR 밝기 설정에 따라 달라집니다(안정 후 낮음 약 4 / 중간 약 3 / 최대 약 2배).

## 2. 요구 환경

| 항목   | 값                                                                                                                          |
| ------ | --------------------------------------------------------------------------------------------------------------------------- |
| macOS  | 27.2                                                                                                                        |
| Safari | 27.2                                                                                                                        |
| Xcode  | 앱이 설치되어 있고 `xcode-select`가 Xcode 앱을 가리켜야 함 (저장소의 `xcode/`는 Xcode 베타 형식, 안정판 호환은 [확인 필요]) |
| 서명   | Apple ID 개인 팀(무료)                                                                                                      |
| 기타   | git                                                                                                                         |

## 3. 최초 설치

1. 저장소를 받습니다(이미 받았으면 생략).
2. Xcode 프로젝트를 만듭니다. 저장소에 `xcode/`가 이미 있으면 이 단계를 건너뜁니다. `xcode/`가 있는 상태에서 실행하면 스크립트가 덮어쓰지 않고 오류로 중단합니다. 저장소 루트에서 한 번만 실행합니다.

```bash
scripts/make-xcode.sh
```

3. `xcode/SDRHDR/SDRHDR.xcodeproj`를 Xcode로 엽니다. 대상(Target)의 Signing에서 개인 팀을 지정하고 Run합니다.
4. `DEVELOPMENT_TEAM` 변경은 커밋하지 않습니다. `git status`에 `xcode/` 변경이 보이면 팀 지정 변경인지 확인합니다.
5. Safari 설정 → 확장 프로그램에서 "SDR HDR"를 켜고 youtube.com 권한을 허용합니다.
6. 확장이 목록에 보이지 않으면 Safari 개발자 메뉴의 "서명되지 않은 확장 허용"을 켭니다. Safari를 재시작할 때마다 다시 켜야 하는지는 [확인 필요]입니다. 재시작 후에는 이 항목이 켜져 있는지 확인합니다.
7. YouTube 영상을 열고 툴바의 확장 아이콘(popup)에서 "켜기"가 체크되어 있는지 봅니다.

## 4. 업데이트 (코드가 바뀐 뒤)

확장 코드(`extension/`)는 Xcode 프로젝트가 폴더로 참조합니다. `make-xcode.sh`를 다시 실행하지 않습니다.

```bash
git pull
```

1. Xcode에서 다시 Run합니다.
2. Safari를 완전히 종료(⌘Q)한 뒤 다시 시작합니다.
3. "서명되지 않은 확장 허용"이 켜져 있는지 다시 확인합니다.
4. YouTube 페이지를 새로고침하고 popup이 최신 구성인지 봅니다. 최신 구성은 위에서부터 켜기, 프리셋, HDR 강도, 선명도, 채도, 유효 피크, 상세 설정(접힘), 페이지 HUD 표시, 진단(접힘) 순서입니다. 이전 구성이면 Run과 Safari 재시작을 다시 합니다.

## 5. 7일 만료와 재서명

- 무료 개인 팀으로 서명한 앱은 약 7일 뒤 만료되어 확장이 꺼지거나 사라질 수 있습니다. 이것은 Apple 정책에 대한 일반 지식이며 이 환경에서의 정확한 기간·증상은 [확인 필요]입니다.
- 만료되면 Xcode에서 다시 Run해 재서명합니다. 코드 변경이 없으면 `git pull`은 필요 없습니다.
- 이후 Safari를 완전 종료(⌘Q) 후 재시작하고, 개발자 메뉴의 "서명되지 않은 확장 허용"과 설정의 확장 켜기·youtube.com 허용을 다시 확인합니다.
- 설정값(프리셋·슬라이더)이 재서명 뒤에도 유지되는지는 [확인 필요]입니다. 같은 Safari 세션에서 popup을 닫았다 열거나 Safari를 재시작해도 유지되는 것은 확인 대상으로 정해져 있습니다(체크리스트 M5).

## 6. popup 사용법

### 일반 영역

| 항목            | 설명                                                         |
| --------------- | ------------------------------------------------------------ |
| 켜기            | 확장 켜기/끄기                                               |
| 프리셋          | 정확 / 균형 / 선명 / 사용자 지정. 선명은 밝기 중간 이상 권장 |
| HDR 강도        | 0%는 색 변환만, 100%는 확장 전체                             |
| 선명도          | 윤곽 선명화. 0%가 꺼짐                                       |
| 채도            | 50~150%                                                      |
| 유효 피크       | `×N.NN` = 1 + 강도 × (하이라이트 밝기 × 밝기 − 1)            |
| 상세 설정       | 접힘. 슬라이더 6개                                           |
| 페이지 HUD 표시 | 영상 위 상태 표시 켜기/끄기                                  |

- 유효 피크가 2.0을 넘으면 "밝기 최대에서 하이라이트가 잘릴 수 있음" 안내가 같은 줄에 나옵니다. SDR 밝기 최대에서 헤드룸이 약 2배이기 때문입니다.
- 상세 슬라이더를 움직이면 프리셋이 "사용자 지정"으로 바뀌고 값이 저장됩니다. 다른 프리셋을 고르면 슬라이더가 그 프리셋 값을 보여 줍니다.
- 슬라이더 값은 약 0.1초 뒤 저장되고 열려 있는 영상에 바로 반영됩니다.

### 상세 설정 슬라이더 (범위는 `params.js`의 `RANGES`)

| 이름            | 키  | 범위      | 단계 |
| --------------- | --- | --------- | ---- |
| 하이라이트 밝기 | P   | 1.0 ~ 8.0 | 0.1  |
| 확장 시작       | k   | 0.4 ~ 0.9 | 0.01 |
| 곡선 지수       | n   | 2.0 ~ 4.0 | 0.1  |
| 밝기            | g   | 0.8 ~ 1.5 | 0.01 |
| 곡선 채도       | s   | 0.8 ~ 1.5 | 0.01 |
| 하이라이트 채도 | hs  | 0.5 ~ 1.5 | 0.01 |

### 현재 기본값 (저장된 값이 없을 때만 적용)

| 항목             | 기본값                                        |
| ---------------- | --------------------------------------------- |
| 프리셋           | 사용자 지정                                   |
| 사용자 지정 곡선 | P 2.0, k 0.40, n 2.0, g 1.22, s 1.03, hs 1.03 |
| HDR 강도         | 43%                                           |
| 선명도           | 0%                                            |
| 채도             | 105%                                          |
| 켜기             | 켜짐                                          |
| 페이지 HUD       | 꺼짐                                          |
| 모드             | itm                                           |

이미 저장된 설정은 그대로 유지되므로 예전 값이 보일 수 있습니다. 설정 초기화 방법은 [확인 필요]입니다.

### 페이지 HUD

켜면 플레이어 왼쪽 위에 5줄이 1초마다 갱신됩니다.

1. 상태(skipReason)와 경로
2. 프리셋·강도·선명·채도
3. 유효 피크
4. fps·JS p95·누락%
5. 영상 해상도

URL·제목은 표시하지 않습니다. 마우스 입력을 막지 않습니다.

### 진단 영역 (접힘)

- 모드: `itm`(기본), `identity`, `stripes`, `baseline`. `itm`이 아니면 일반 영역의 셰이더 슬라이더가 비활성화됩니다. 진단용이므로 평소에는 `itm`으로 둡니다.
- `baseline`: 캔버스를 숨겨 원본이 보이고 렌더를 하지 않습니다. 확장이 끊김에 미치는 영향을 비교할 때 씁니다.
- 진단 JSON: "복사" 버튼으로 클립보드에 복사합니다. "JSON 저장" 링크의 Safari popup 동작은 [확인 필요]이므로 복사를 기본으로 합니다.

## 7. 문제 해결

### 영상이 원본 그대로일 때

popup의 "진단"을 펼쳐 JSON에서 아래를 봅니다.

| 필드                        | 볼 것                                  |
| --------------------------- | -------------------------------------- |
| `lifecycle.state`           | `active`면 동작 중, `skipped`면 건너뜀 |
| `lifecycle.skipReason`      | 건너뛴 사유                            |
| `errors`                    | 오류 이름 목록                         |
| `flags`                     | 감지 플래그                            |
| `video.colorSpace.transfer` | `pq` 또는 `hlg`면 HDR 원본             |

사유별 의미:

| `skipReason` | 의미                                                                               | 조치                                          |
| ------------ | ---------------------------------------------------------------------------------- | --------------------------------------------- |
| `drm`        | DRM 신호 감지. 같은 탭에서는 이후 일반 영상에서도 유지되며 새로고침하면 해제됩니다 | 정상 동작, 조치 없음                          |
| `hdrSource`  | 원본이 HDR(`transfer`가 pq/hlg)                                                    | 정상 동작, 조치 없음                          |
| `pip`        | PiP 중                                                                             | PiP 종료 후 재개되는지 확인                   |
| `blackFrame` | 입력 프레임이 검게 연속으로 읽혀 중단                                              | 진단 JSON을 보관하고 [확인 필요: 재시도 방법] |
| `noGpu`      | WebGPU를 쓸 수 없음                                                                | Safari·OS 버전과 WebGPU 설정 확인             |
| `disabled`   | popup에서 꺼져 있음                                                                | "켜기" 체크 확인                              |

- 셰이더 컴파일 실패: 영상이 원본 그대로이고 `errors`에 `uncapturederror`가 남습니다. JSON을 보관해 보고합니다.
- `lifecycle.state`가 `active`인데 변화가 약하면 강도·유효 피크와 SDR 밝기(헤드룸)를 확인합니다. 밝기가 낮을수록 헤드룸이 큽니다.

### 끊김이 느껴질 때

1. 페이지 HUD를 켜고 fps와 누락%를 봅니다.
2. popup에서 확장을 끄거나 모드를 `baseline`으로 두고 같은 영상을 비교합니다. 확장을 꺼도 같은 끊김이면 원본 재생 쪽 현상입니다.
3. 전원 연결, 저전력 모드 끔 상태에서 비교합니다.
4. 진단 JSON을 복사해 보관합니다.

### 광고·SPA 이동

- 영상 이동(SPA)은 이벤트와 DOM 관찰로 감지해 다음 영상에서도 자동으로 다시 붙습니다.
- 광고에서 본편으로 바뀔 때 오버레이가 유지되는지는 아직 확인하지 못했습니다(8장).

### 개인정보

진단 JSON에는 영상 제목, 채널, 쿠키, 계정 정보, 전체 URL이 없습니다. 페이지는 경로와 `v` 값만 기록합니다. 최신 1개만 `storage.local`에 보관하고 외부로 전송하지 않습니다.

## 8. 알려진 제한과 미검증

- 60Hz 설정에서 Safari의 rAF가 약 30회/s로 관찰됨(A24). 확장과 프로브 모두 같고 원인은 확인하지 못했습니다. 확장 켬과 `baseline` 비교는 M6에서 측정 예정입니다.
- 24·25·30fps 등 비60fps 소스의 끊김은 확장 탓인지 원본 cadence 탓인지 분리하지 못했습니다. 측정 예정입니다.
- 전체화면에서의 비용은 아직 측정하지 않았습니다. 측정 예정입니다(M6).
- 4K HDR 영상을 처음 열 때의 멈칫함은 M6 측정 전입니다. 측정 예정입니다.
- 광고, PiP 복귀, 미니플레이어, 극장 모드 동작은 미확인입니다(M3 [미확인]).
- WebGPU 출력, EDR 밝기, 끊김은 사용자 Mac에서 눈으로 확인하는 항목이며 자동 테스트로 검증하지 않았습니다.
- 확인 절차와 기록 방법은 `docs/manual-checklist.md`를 따릅니다.
