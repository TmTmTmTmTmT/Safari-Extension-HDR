# 설치·사용·문제 해결 가이드

SDR 영상을 실시간으로 확장해 EDR(HDR 밝기)로 보여 주는 Safari 확장입니다. 처음 설치할 때, 업데이트할 때, 서명이 만료돼 다시 설치할 때 이 문서를 따릅니다. 확인하지 못한 내용은 `[확인 필요]`로 표시했습니다.

## 1. 개요와 한계

- 주 대상은 YouTube(`https://www.youtube.com/*`)의 DRM 없는 SDR 영상입니다.
- 아래 경우는 의도적으로 건너뛰고 원본 그대로 재생합니다. 오류가 아닙니다.
  - DRM(EME/FairPlay) 영상: 신호가 하나라도 있으면 즉시 아무것도 하지 않습니다. DRM 회피·화면 캡처 우회는 하지 않습니다.
  - 이미 HDR인 영상(PQ/HLG)
  - PiP(화면 속 화면): PiP에서는 원본 재생, 복귀 시 재개되는지는 아직 확인하지 못했습니다(8장).
- 지원 대상: macOS 26 이상, Safari 26 이상(WebGPU 필요), EDR 디스플레이. 실측은 M1 Pro, 내장 XDR, macOS 27.2, Safari 27.2뿐입니다. Safari 26.x에서의 동작은 [확인 필요]입니다. WebGPU가 없는 Safari에서는 popup에 "이 Safari는 WebGPU를 지원하지 않음: 원본 표시"가 보이고 영상은 원본으로 재생됩니다.
- 화면 밝기 헤드룸은 JS에서 조회할 수 없고 화면 밝기(SDR 밝기) 설정에 따라 달라집니다(안정 후 낮음 약 4 / 중간 약 3 / 최대 약 2배).

## 3. 최초 설치 (GitHub에서 받은 사용자)

### 3-1. 자동 설치 (권장)

```bash
git clone https://github.com/TmTmTmTmTmT/Safari-Extension-HDR.git && cd Safari-Extension-HDR
scripts/install.sh
```

스크립트가 아래를 자동으로 합니다.

1. 환경 점검: macOS 26+, Safari 26+, Xcode 선택·최초 실행 구성, 프로젝트 열림. 실패하면 할 일을 알려 주고 멈춥니다.
2. 서명 팀 찾기: 키체인의 Apple Development 인증서에서 팀 ID를 자동으로 찾습니다(여러 개면 번호 선택). 인증서가 없으면 "Xcode › 설정 › 계정에서 Apple ID 추가" 후 다시 실행하라고 안내합니다.
3. 서명 빌드: 팀·배포 타깃·버전을 명령행으로만 넘깁니다. `xcode/` 프로젝트 파일은 수정하지 않으므로 `git status`가 깨끗하게 유지됩니다.
4. 이전 사본 정리: `/Applications`·DerivedData 등의 이전 SDR HDR를 목록으로 보이고, 확인 한 번 뒤 휴지통으로 옮깁니다(영구 삭제 안 함).
5. `/Applications`에 설치하고 앱을 엽니다(설정 점검 화면).
6. Safari 재시작 여부를 묻습니다(기본 아니오).

받는 방법: `git clone`, 필요한 폴더만 받는 sparse checkout(README 참고), GitHub ZIP 모두 가능합니다. ZIP은 `.git`이 없어 `--update`를 쓸 수 없습니다(새 ZIP으로 다시 설치). 서명·빌드는 어느 경우든 받는 사람의 Mac에서 그 사람의 개인 팀으로 합니다.

옵션: `--update`(먼저 `git pull --ff-only`), `-y`(확인 생략, Safari는 재시작하지 않음), `--no-open`(앱 실행·Safari 재시작 생략), `--dry-run`(명령만 출력, 아무것도 바꾸지 않음).

자동화하지 않는 것(직접 해야 함): Apple ID를 Xcode에 로그인하는 것(처음 한 번), Safari 설정 › 확장 프로그램에서 SDR HDR 켜기, 웹사이트 접근에서 www.youtube.com 허용. 열린 SDR HDR 창의 점검 목록이 남은 항목을 알려 줍니다. 서명이 팀으로 확인되면 "서명되지 않은 확장 허용"은 보통 필요 없고, **켜 두었다면 꺼 두세요**(켜져 있는 동안은 서명되지 않은 다른 확장도 로드될 수 있습니다). 2026-10-06 관측, macOS 27.2 · Safari 27.2, 다른 환경 [확인 필요].

### 3-2. 수동 설치 (Xcode에서 Run)

1. 저장소를 받습니다: `git clone https://github.com/TmTmTmTmTmT/Safari-Extension-HDR.git` 후 해당 폴더로 이동.
2. Xcode 프로젝트는 저장소의 `xcode/`에 이미 있습니다. `scripts/make-xcode.sh`는 `xcode/`가 없을 때만 쓰며, 있는 상태에서 실행하면 덮어쓰지 않고 오류로 중단합니다.
3. `xcode/SDRHDR/SDRHDR.xcodeproj`를 Xcode로 엽니다(저장소의 프로젝트는 Xcode 베타 형식이라 같은 형식을 여는 Xcode가 필요합니다. 안정판 호환은 [확인 필요]).
4. **SDRHDR와 SDRHDR Extension 두 타깃 모두** Signing & Capabilities에서 Team을 개인 팀(Apple ID, 무료)으로 지정합니다. `DEVELOPMENT_TEAM` 변경은 커밋하지 않습니다. 이 단계가 빠지면 Safari가 확장을 서명되지 않은 것으로 보고 재시작마다 "서명되지 않은 확장 허용"을 요구합니다.
5. Run합니다. SDR HDR 앱 창(**설정 안내 화면**)이 뜹니다. 이 화면이 아래를 점검해 줍니다.
   1. 서명: 두 타깃 모두 팀 서명이면 완료. 아니면 4번을 안내합니다.
   2. 사본: SDR HDR가 여러 개 설치돼 있으면 목록을 보이고, 이 앱이 가장 최신일 때 이전 사본을 **휴지통으로 이동**(파일 선택 창에서 직접 확인)할 수 있습니다. 더 최신 사본이 있으면 "최신 사본 열기"를 안내합니다. 사본을 정리한 뒤 Safari를 완전히 종료(⌘Q)하고 다시 여세요.
   3. 확장 켜짐: 꺼져 있으면 "Safari 확장 설정 열기"로 Safari 설정 › 확장 프로그램에서 SDR HDR를 켭니다. 앱은 종료되지 않고, 돌아오면 다시 점검합니다.
   4. www.youtube.com 접근(직접 확인): 확장 설정의 웹사이트 접근에서 "허용한 사이트에서"를 고르고 www.youtube.com이 목록에 있는지 확인한 뒤 "확인했어요"를 체크합니다.
   5. 모두 완료되면 "시작하기"를 눌러 창을 닫습니다(앱 종료).
6. 안내 화면 1번이 완료(개인 팀 서명 확인)인데도 Safari 설정에 확장이 보이지 않을 때만 Safari 설정 → 고급에서 "웹 개발자용 기능 보기"를 켜고 개발자 메뉴의 "서명되지 않은 확장 허용"을 켭니다. 확장이 보이고 동작하는 것을 확인한 뒤에는 이 옵션을 다시 끄세요. 이 옵션은 Safari를 재시작하면 꺼집니다(2026-10-02 사용자 확인). 팀 서명 상태에서는 필요 없었다는 관측이 있습니다(2026-10-06, macOS 27.2 · Safari 27.2, 원인 [추정], 다른 환경 [확인 필요]).
7. `www.youtube.com` 영상을 열고 새로고침한 뒤 툴바의 확장 아이콘(popup)을 엽니다. 헤더의 "HDR 변환" 스위치가 켜져 있고 버전이 보이는지 확인합니다.

앱을 Finder에서 직접 열면 같은 안내 화면이 뜹니다. 로그인(재부팅) 때 시스템이 앱을 다시 열면 창 없이 백그라운드로 뜹니다(Dock 아이콘 없음). 판정 로그: `/usr/bin/log show --predicate 'subsystem == "io.github.tmtmtmtmtmt.SDRHDR"' --last 10m --info` (zsh에서는 `log`가 내장 명령이라 `/usr/bin/log`로 씁니다).

## 4. 업데이트 (코드가 바뀐 뒤)

```bash
scripts/install.sh --update
```

`git pull --ff-only` → 빌드 → 이전 사본 정리 → 설치 → 앱 실행까지 같은 순서로 다시 합니다. 팀 ID는 `.local/team-id`에 저장돼 있어 다시 묻지 않습니다. 끝난 뒤 Safari를 완전히 종료(⌘Q)하고 다시 열어 popup 헤더 버전이 `extension/manifest.json`의 `version`과 같은지 확인합니다.

수동(Xcode) 설치를 쓰는 경우에는 `git pull` → Xcode에서 다시 Run → Safari ⌘Q 후 재시작 순서입니다. `make-xcode.sh`는 다시 실행하지 않습니다. 이 경로는 DerivedData 사본이 생기므로 앱의 점검 화면이 사본 정리를 제안합니다.

## 5. 서명 만료와 재서명

- 무료 개인 팀으로 서명한 앱은 일정 기간(Apple 정책상 약 7일로 알려져 있으나 이 환경에서의 정확한 기간·증상은 [확인 필요]) 뒤 만료되어 확장이 꺼지거나 사라질 수 있습니다.
- 확장이 사라졌다면 `scripts/install.sh`를 다시 실행하거나(권장) Xcode에서 다시 Run해 재서명합니다. 코드 변경이 없으면 `git pull`은 필요 없습니다.
- 이후 Safari를 완전 종료(⌘Q) 후 재시작하고, 열린 SDR HDR 점검 화면이 서명 확인(✓)이면 개발자 메뉴의 "서명되지 않은 확장 허용"은 필요 없고 꺼 두는 것이 안전합니다. 서명이 확인되지 않는 경우에만 3-2의 6번을 참고하세요. 설정의 확장 켜기·youtube.com 허용은 다시 확인합니다.
- 설정값(프리셋·슬라이더)이 재서명 뒤에도 유지되는지는 [확인 필요]입니다. 같은 Safari 세션에서 popup을 닫았다 열거나 Safari를 재시작해도 유지되는 것은 확인 대상으로 정해져 있습니다(체크리스트 M5, `docs/archive/manual-checklist-m1-m6.md`).

## 6. popup 사용법

### 현재 탭 상태 (popup 맨 위, M8)

헤더 아래 상태 줄이 지금 보고 있는 탭의 상태를 1초마다 보여 줍니다(진단 영역의 "마지막 기록"과 달리 현재 탭 기준). 예: "HDR 변환 중", "판정 중(원본 표시)", "이미 HDR 영상: 원본 표시", "DRM 영상: 변환하지 않음", "PiP 중: 원본 표시", "입력이 검게 읽혀 중단", "렌더 오류(…)", "꺼짐", "진단 모드: HDR 변환 안 함". 조치가 필요하면 아래에 한 줄 안내가 붙습니다.

- "이 탭에서는 동작하지 않음"이 보이면 대상 페이지(www.youtube.com 영상 페이지, 임베드·music.youtube.com 제외)가 아니거나, Safari 설정 › 확장 › SDR HDR에서 www.youtube.com 접근이 허용되지 않은 것입니다. 허용 후 새로고침합니다.
- 상태 줄은 popup이 현재 탭에 직접 묻는 방식입니다. Safari에서 권한 없이 동작하는지는 [확인 필요]입니다(안 되면 `activeTab` 권한을 추가).
- "이전 DRM 영상 때문에 이 탭에서는 변환 중지"는 같은 탭에서 DRM 영상을 본 뒤의 정상 동작입니다. 새로고침(⌘R)하면 다시 동작합니다.

### 툴바 배지와 아이콘 (M8)

- 배지: 이미 HDR 영상 "HDR", 진단 모드 "D", 판정 중 "…", 건너뜀 "–", 오류 "!". 정상 변환 중과 꺼짐은 배지가 없습니다.
- 확장을 끄면 툴바 아이콘이 회색이 됩니다. 배지·아이콘 표시와 background 동작은 Safari 27.2에서 [확인 필요]입니다(로드되지 않으면 manifest의 background 형식을 `scripts` 형식으로 바꾸는 대안이 있음).

### 단축키와 상태 알림 (M8)

- Option+H를 누르고 있는 동안 원본을 봅니다(현재 탭만, 떼면 즉시 복귀). 변환 중·판정 중일 때만 동작합니다.
- Option+Shift+H는 HDR 변환 켜기/끄기입니다(모든 탭 공통, popup 스위치와 같음).
- 입력창에 글자를 입력하는 중에는 동작하지 않습니다.
- 상태가 바뀔 때 영상 오른쪽 위에 2.5초 동안 상태 알림이 뜹니다. popup의 "상태 알림"으로 끕니다(단축키 안내 문구는 항상 표시).

### 일반 영역

| 항목                   | 설명                                                                                               |
| ---------------------- | -------------------------------------------------------------------------------------------------- |
| HDR 변환 (헤더 스위치) | 확장 켜기/끄기(켜짐/꺼짐)                                                                          |
| 프리셋                 | 정확 / 균형 / 강조 / 사용자 지정. 강조는 화면 밝기 중간 이하 권장                                  |
| HDR 강도               | 0%는 색 변환만, 100%는 확장 전체                                                                   |
| 유효 피크              | HDR 강도 슬라이더 바로 아래. `×N.NN` = 1 + 강도 × (f(g) − 1)                                       |
| 선명도                 | 윤곽 선명화. 0%가 꺼짐                                                                             |
| 채도                   | 50~150%                                                                                            |
| 상세 설정              | 접힘. 슬라이더 6개                                                                                 |
| 페이지 HUD 표시        | 영상 위 상태 표시 켜기/끄기                                                                        |
| 기본값으로 되돌리기    | 버튼을 두 번 눌러 확인. 대상은 프리셋·사용자 지정 곡선·강도·선명도·채도·HUD. 켜기·진단 모드는 유지 |

- 유효 피크의 f는 셰이더 곡선이고, 전체 밝기(g)를 곡선 앞에서 곱한 값을 넣습니다. g=1이면 기존 `1 + 강도 × (P − 1)`과 같고, g≠1이면 f(g)가 P × g보다 클 수 있습니다. 기본값에서 표시는 ×1.90입니다(이전 문서의 ×1.62는 낡은 값입니다).
- 유효 피크가 2.0을 넘으면 "화면 밝기 최대에서 하이라이트가 잘릴 수 있음" 안내가 같은 줄에 나옵니다. 화면 밝기 최대에서 헤드룸이 약 2배이기 때문입니다.
- 이 문서에서 "화면 밝기"는 macOS 밝기이고, 상세 슬라이더 "전체 밝기(g)"는 영상 전체에 곱하는 값입니다. 둘은 다릅니다.
- 상세 슬라이더를 움직이면 프리셋이 "사용자 지정"으로 바뀌고 값이 저장됩니다. 다른 프리셋을 고르면 슬라이더가 그 프리셋 값을 보여 줍니다.
- 슬라이더 값은 약 0.1초 뒤 저장되고 열려 있는 영상에 바로 반영됩니다.
- 기본값으로 되돌리기는 popup 화면에서 하며, 동작은 코드·단위 테스트 기준이고 기기에서 확인한 것이 아닙니다 [확인 필요: 사용자 Mac].

### 내 프리셋 (1.3.0)

프리셋 선택 바로 아래 "내 프리셋 (N)"(기본 접힘)에서 현재 화질 설정에 이름을 붙여 저장하고, 골라 불러오고, 지웁니다.

- **저장되는 값**: 곡선 6개(하이라이트 밝기·확장 시작·곡선 지수·전체 밝기·곡선 채도·하이라이트 채도), HDR 강도, 선명도, 채도. 켜기·진단 모드·HUD·상태 알림은 저장하지 않습니다. 이름 있는 프리셋(정확·균형·강조)을 쓰는 중에 저장하면 그 프리셋의 곡선 값이 저장됩니다.
- **저장**: 이름(1~20자)을 입력하고 [현재 설정 저장]. 같은 이름이면 버튼이 "덮어쓰기 확인"으로 바뀌고 한 번 더 눌러야 덮어씁니다(3초 안). 최대 20개이며 가득 차면 하나를 삭제한 뒤 저장합니다.
- **불러오기**: 목록에서 고르고 [불러오기]. 프리셋은 "사용자 지정"으로 바뀌고 슬라이더 값이 즉시 반영됩니다. 현재 사용자 지정 곡선이 달라지면 "이전 사용자 지정 곡선을 … 바꿨습니다 [되돌리기]"로 되돌릴 수 있습니다.
- **삭제**: [삭제]를 두 번 눌러 확인합니다(3초 안).
- "기본값으로 되돌리기"는 내 프리셋을 지우지 않습니다. 내 프리셋은 설정 백업(재시작 뒤 복원, 7장 "설정이 기본값으로 돌아갔을 때")에 포함됩니다. 진단 모드일 때는 저장·불러오기·삭제가 잠깁니다.
- 실제 동작은 사용자 Mac에서 확인 전입니다 [확인 필요].

### 상세 설정 슬라이더 (범위는 `params.js`의 `RANGES`)

popup 라벨은 '하이라이트 밝기(P)', '확장 시작(k)', '곡선 지수(n)', '전체 밝기(g)', '곡선 채도(s)', '하이라이트 채도(hs)'입니다.

| 이름            | 키  | 범위      | 단계 |
| --------------- | --- | --------- | ---- |
| 하이라이트 밝기 | P   | 1.0 ~ 8.0 | 0.1  |
| 확장 시작       | k   | 0.4 ~ 0.9 | 0.01 |
| 곡선 지수       | n   | 2.0 ~ 4.0 | 0.1  |
| 전체 밝기       | g   | 0.8 ~ 1.5 | 0.01 |
| 곡선 채도       | s   | 0.8 ~ 1.5 | 0.01 |
| 하이라이트 채도 | hs  | 0.5 ~ 1.5 | 0.01 |

### 현재 기본값 (저장된 값이 없을 때만 적용)

| 항목             | 기본값                                        |
| ---------------- | --------------------------------------------- |
| 프리셋           | 사용자 지정                                   |
| 사용자 지정 곡선 | P 2.0, k 0.40, n 2.0, g 1.22, s 1.03, hs 1.03 |
| HDR 강도         | 43%                                           |
| 선명도           | 0%                                            |
| 채도             | 105%                                          |
| HDR 변환         | 켜짐                                          |
| 페이지 HUD       | 꺼짐                                          |
| 모드             | itm                                           |

이미 저장된 설정은 그대로 유지되므로 예전 값이 보일 수 있습니다. popup의 "기본값으로 되돌리기"로 위 표의 설정(켜기·진단 모드 제외)을 되돌릴 수 있습니다. Safari 확장 저장 데이터 자체를 삭제하는 방법은 [확인 필요]입니다.

### 페이지 HUD

popup의 "페이지 HUD 표시"를 켜면 보이는 상태 표시입니다(기본 꺼짐). 켜면 플레이어 왼쪽 위에 5줄이 1초마다 갱신됩니다. 진단 모드에서는 2·3줄에 "(미적용)", 일시정지 중에는 4줄에 "일시정지: 정지 직전 값"이 붙습니다.

1. 상태(한국어 문구와 원래 id)와 경로
2. 프리셋 · 강도 …% 선명도 …% 채도 …%
3. 유효 피크
4. 렌더 fps(영상 fps가 아니라 렌더 루프 횟수)·JS p95·누락%
5. 영상 해상도

URL·제목은 표시하지 않습니다. 마우스 입력을 막지 않습니다. DRM·WebGPU 실패·확장 끔에서도 HUD가 유지되어 이유를 보여 줍니다(M8).

### 진단 영역 (접힘)

- 모드: `itm`(기본), `identity`, `stripes`, `baseline`. `itm`이 아니면 일반 영역의 셰이더 슬라이더가 비활성화되고 진단 영역이 자동으로 펼쳐지며 [정상 모드로] 버튼이 나옵니다. 진단용이므로 평소에는 `itm`으로 둡니다.
- `baseline`: 캔버스를 숨겨 원본이 보이고 렌더를 하지 않습니다. 확장이 끊김에 미치는 영향을 비교할 때 씁니다.
- 진단 JSON: popup의 "진단" 영역을 펼치면 현재 탭에 직접 물어 약 2초마다 갱신합니다(1.3.1부터 저장소에 쓰지 않음)(영역을 접으면 갱신하지 않음). "복사" 버튼으로 클립보드에 복사하면 "복사됨"이 표시됩니다. 진단 출처 줄('마지막 기록 …')로 어느 시점의 진단인지 봅니다. 진단 모드를 바꿨다면 측정 뒤 popup 진단 영역의 [정상 모드로]로 되돌립니다. 진단 schemaVersion은 13이며, v11 이하의 `render.effectivePeak`는 빌드에 따라 공식이 달라 g≠1에서 직접 비교하지 않습니다(extVersion 1.1.0 미만은 옛 공식). "JSON 저장" 링크의 Safari popup 동작은 [확인 필요]이므로 복사를 기본으로 합니다.

## 7. 문제 해결

### 영상이 원본 그대로일 때

popup의 "진단"을 펼쳐 JSON에서 아래를 봅니다.

| 필드                        | 볼 것                                  |
| --------------------------- | -------------------------------------- |
| `lifecycle.state`           | `active`면 동작 중, `skipped`면 건너뜀 |
| `lifecycle.skipReason`      | 건너뛴 사유                            |
| `errors`                    | 오류 이름 목록                         |
| `flags`                     | 감지 플래그                            |
| `video.colorSpace.transfer` | `pq` 또는 `hlg`면 HDR 원본             |

사유별 의미:

| `skipReason` | 의미                                                                                                                                          | 조치                                                                                                             |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `drm`        | DRM 신호 감지. 같은 영상 요소에서 영구 건너뜀이며 재시도 대상이 아닙니다. 같은 탭에서는 이후 일반 영상에서도 유지되고 새로고침하면 해제됩니다 | 정상 동작, 조치 없음                                                                                             |
| `hdrSource`  | 원본이 HDR(`transfer`가 pq/hlg)                                                                                                               | 정상 동작, 조치 없음                                                                                             |
| `pip`        | PiP 중                                                                                                                                        | PiP 종료 후 재개되는지 확인                                                                                      |
| `blackFrame` | 입력 프레임이 검게 연속으로 읽혀 중단                                                                                                         | 다른 영상으로 이동하거나, popup에서 HDR 변환을 껐다 켜거나, 새로고침하면 다시 판정(코드 기준, 기기에서는 미확인) |
| `noGpu`      | 렌더러 오류 전반(WebGPU 없음·device lost·셰이더 오류 등)                                                                                      | 진단 `errors`의 name 확인 → 껐다 켜기 또는 새로고침, 반복되면 Safari 재시작                                      |
| `disabled`   | popup에서 꺼져 있음                                                                                                                           | "HDR 변환" 스위치 확인                                                                                           |

- 셰이더 컴파일 실패: 영상이 원본 그대로이고 `errors`에 `uncapturederror`가 남습니다. JSON을 보관해 보고합니다.
- `lifecycle.state`가 `active`인데 변화가 약하면 강도·유효 피크와 화면 밝기(헤드룸)를 확인합니다. 화면 밝기가 낮을수록 헤드룸이 큽니다.

### 끊김이 느껴질 때

1. 페이지 HUD를 켜고 렌더 fps와 누락%를 봅니다.
2. popup에서 HDR 변환을 끄거나 모드를 `baseline`으로 두고 같은 영상을 비교합니다. 확장을 꺼도 같은 끊김이면 원본 재생 쪽 현상입니다.
3. 전원 연결, 저전력 모드 끔 상태에서 비교합니다.
4. 진단 JSON을 복사해 보관합니다.

### 광고·SPA 이동

- 영상 이동(SPA)은 이벤트와 DOM 관찰로 감지해 다음 영상에서도 자동으로 다시 붙습니다.
- 광고에서 본편으로 바뀔 때 오버레이가 유지되는지는 아직 확인하지 못했습니다(8장).

### 설정이 기본값으로 돌아갔을 때 (1.2.1)

Xcode에서 다시 Run 하거나 Mac을 재부팅한 뒤 슬라이더 값이 기본값으로 돌아가는 현상이 보고됐습니다. Safari가 서명되지 않은 확장의 저장소를 새로 시작하는 것으로 추정합니다 [확인 필요]. 1.2.1부터는 값을 바꾸면 1초 뒤 Mac 앱 쪽 저장소에도 백업하고, Safari가 다시 시작됐을 때 확장 저장소가 비어 있으면 백업에서 되살립니다. 되살렸으면 popup 진단 영역에 "재시작 후 설정을 백업에서 복원함"이 보입니다. 진단 모드는 백업하지 않습니다(재시작 뒤 항상 정상 모드). 이 기능은 `nativeMessaging` 권한과 background가 Safari에서 로드되어야 동작하며, 실제 동작은 [확인 필요]입니다.

### "Disk I/O error" (Safari 설정 › 확장 프로그램 창 맨 아래)

Safari의 확장 저장소가 쓰기를 거부한 오류입니다. 1.3.1부터 진단은 저장소에 쓰지 않아 쓰기 횟수가 크게 줄었고, 설정 저장·재시작 후 복원이 실패하면 다시 시도합니다(설정 저장 1회, 복원 최대 3회). 그래도 popup에 "저장 실패(Safari 저장소 오류)"가 보이거나 설정이 초기화됐다는 안내가 나오면 Safari를 완전히 종료(⌘Q) 후 다시 열고, 필요하면 "내 프리셋"에서 불러옵니다. 원인(Safari 내부)은 [확인 필요]입니다.

### 개인정보

진단 JSON에는 영상 제목, 채널, 쿠키, 계정 정보, 전체 URL이 없습니다. 페이지는 경로와 `v` 값만 기록합니다. 최신 1개만 `storage.local`에 보관하고 외부로 전송하지 않습니다.

## 8. 알려진 제한과 미검증

- 4K 재생 중 `kernel_task`와 Safari 페이지 메모리가 크게 늘어나는 현상(합계 약 13 GB)이 보고됐습니다. 1.2.1에서 GPU 처리 대기가 쌓이면 렌더를 건너뛰는 상한을 넣었고, 원인은 체크리스트 "U 회차 확인"의 측정으로 가립니다.
- 60Hz 설정에서 Safari의 rAF가 약 30회/s로 관찰됨(A24). 확장과 프로브 모두 같고 원인은 확인하지 못했습니다. 확장 켬과 `baseline` 비교는 M6에서 측정 예정입니다.
- 24·25·30fps 등 비60fps 소스의 끊김은 확장 탓인지 원본 cadence 탓인지 분리하지 못했습니다. 측정 예정입니다.
- 전체화면에서의 비용은 아직 측정하지 않았습니다. 측정 예정입니다(M6).
- 4K HDR 영상을 처음 열 때의 멈칫함은 M6 측정 전입니다. 측정 예정입니다.
- 광고, PiP 복귀, 미니플레이어, 극장 모드 동작은 미확인입니다(M3 [미확인]).
- WebGPU 출력, EDR 밝기, 끊김은 사용자 Mac에서 눈으로 확인하는 항목이며 자동 테스트로 검증하지 않았습니다.
- 확인 절차와 기록 방법은 `docs/manual-checklist.md`를 따릅니다.

## 9. 끄기·제거

제거 후 저장값이 남는지는 [확인 필요]입니다.

1. 잠시 끄기: popup 헤더의 "HDR 변환"을 끕니다. 저장값은 유지됩니다.
2. Safari에서 끄기: Safari 설정 → 확장 프로그램에서 "SDR HDR" 체크를 해제합니다.
3. 제거: Xcode의 Product > Show Build Folder in Finder로 빌드 폴더를 열고 `SDRHDR.app`을 삭제한 뒤 Safari를 완전 종료(⌘Q) 후 재시작합니다. 이 메뉴로 빌드 폴더의 `SDRHDR.app`이 보이는 것은 확인했습니다(2026-10-02). 삭제 뒤 저장값이 남는지는 [확인 필요]입니다.
4. 앱 다시 열기: 창을 닫으면 앱이 종료되므로, Xcode에서 다시 Run하거나 빌드 폴더의 `SDRHDR.app`을 엽니다.
